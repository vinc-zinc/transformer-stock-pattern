# Temporal Transformer vs CNN-BiLSTM — Stock Forecasting Dashboard

An interactive Streamlit dashboard visualizing a deep-learning coursework
project that forecasts 5-trading-day-ahead stock prices for 49 large-cap
tickers, comparing a **Temporal Transformer** (self-attention encoder) against
a **CNN-BiLSTM** (residual convolutions + squeeze-excite attention + BiLSTM),
both trained on the same 20-year daily OHLCV dataset.

The dashboard covers: raw price/indicator data exploration, model
architecture summaries, training curves, actual-vs-predicted price charts,
gradient-based feature importance, Transformer self-attention heatmaps, and
a head-to-head model comparison (including a random-walk baseline).

## How it's structured

The deployed app never imports TensorFlow and never trains anything live.
Training happens **once**, offline, via `scripts/train_and_export.py`, which
writes small CSV/JSON/NPZ artifacts into `data/processed/`. The Streamlit
app only reads those artifacts. This keeps the deployed app fast, free of
GPU/CPU training cost per visitor, and deployable on the free tier of
Streamlit Community Cloud.

```
transformer-stock-dashboard/
├── app.py                        # landing page
├── pages/                        # one file per dashboard page (Streamlit
│                                  # auto-discovers files here for the sidebar)
├── src/
│   ├── data_pipeline.py          # feature engineering, target, windowing, split
│   ├── models.py                 # both model architectures (TensorFlow)
│   └── load_artifacts.py         # cached readers for data/processed/*
├── scripts/
│   ├── train_and_export.py       # one-off: trains both models, exports artifacts
│   └── requirements-train.txt    # extra deps needed ONLY for training
├── data/
│   ├── raw/                      # top_companies_20y_daily_combined.csv
│   └── processed/                # generated by train_and_export.py
├── notebooks/                    # original coursework notebooks (reference)
└── requirements.txt              # deps for the deployed app itself
```

## Running locally

### 1. View the dashboard with the already-trained results

If `data/processed/` already has the exported artifacts (metrics.json,
training_history.json, feature_importance.json, attention_weights.npz,
per_ticker_mape.csv, test_predictions.csv, engineered_features.csv.gz),
you can go straight to:

```bash
pip install -r requirements.txt
streamlit run app.py
```

### 2. Regenerate the artifacts yourself (retrain both models)

```bash
pip install -r requirements.txt -r scripts/requirements-train.txt
python scripts/train_and_export.py
```

This re-runs the full data pipeline (feature engineering → per-ticker
expanding-window normalization → 20-day sliding windows → chronological
train/val/test split), trains both models with early stopping (max 15
epochs, patience 5 on validation loss — the same architecture defaults used
in the original coursework grid search), evaluates them on the held-out
test set (2020 onward), and writes every artifact the dashboard needs into
`data/processed/`. On a CPU-only machine this takes roughly 20–35 minutes
total for both models.

## Deploying for free (Streamlit Community Cloud)

1. Push this repo to GitHub (see below).
2. Go to [share.streamlit.io](https://share.streamlit.io), sign in with
   GitHub, and click "New app".
3. Point it at this repo, branch `main`, main file `app.py`.
4. Deploy. Streamlit Cloud installs `requirements.txt` automatically — no
   TensorFlow needed since the app only reads precomputed files.

Make sure `data/processed/*.json`, `*.csv`, `*.csv.gz`, and `*.npz` are
committed (the `.gitignore` excludes only the large `.keras` model weight
files, which the deployed app doesn't need).

## Methodology summary

- **Target:** predict `price[t+5] / price[t]` (a ratio, not a raw price),
  clipped to [0.60, 1.55] to reduce the influence of extreme outliers.
- **Features (10, per ticker):** log return, SMA/EMA spread, RSI, Bollinger
  %B, ATR ratio, volume ratio, OBV momentum, VWAP deviation, price/volume
  divergence.
- **Normalization:** per-ticker *expanding*-window z-score (252-day
  minimum warm-up), so no future information leaks into any training
  window.
- **Windowing:** 20-day lookback sliding windows.
- **Split:** chronological, not random — train ≤ 2017, validation
  2018–2019, test ≥ 2020 — to avoid look-ahead bias.
- **Loss:** Huber (δ=0.03). **Metrics:** MAE, RMSE, MAPE, RMSPE, bias,
  directional accuracy, all benchmarked against a random-walk (no-change)
  baseline.
